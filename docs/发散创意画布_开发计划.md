# 发散创意画布桌面应用 · 开发计划（小步迭代版）

> 配套文档：`docs/发散创意画布桌面应用_方案.md`（纲领）、`docs/发散创意画布_实现计划_Phase0-1.md`（架构与代码骨架）
> 本文件是**执行层面的开发计划**，核心原则：**一个功能一步、做一步验证一步、每步本地提交、确认后再上传。**

---

## 0. 总原则与节奏

1. **极小步**：每个步骤只完成"一个可独立验证的功能点"，不贪大。
2. **先验证后继续**：每步做完，先按"验证方法"自测通过，再进入下一步。
3. **小步提交**：每步自测通过后，`git commit` 到本地 `main`（提交信息带步骤号，如 `step 3.2 deepseek adapter`）。
4. **确认后上传**：**不自动 push**。每完成一个阶段（或你口头确认"这步 OK"）后，才 `git push origin main`。
5. **可回退**：任一步验证失败，立即停下汇报，不强行往下做；必要时 `git revert` 该步提交回到干净状态。

**D.4 缩略图「快速定位」修复**
- 现象（用户反馈）：右下角的缩略窗口（MiniMap）**不能用** —— 拖不动、点不动。
- **定位过程（先证伪环境，再定代码）**：诊断探针实测缩略图 `200×150`、可见、未被遮挡、也画出了 4/4 个节点 → 说明"渲染没问题"，问题在**交互没被启用**。用真实鼠标点击后视口 transform 不变，**合成 PointerEvent 也不变** → 排除"注入姿势不对"，确认是真 bug。
- **根因（读依赖源码得到，不是猜）**：
  - `@xyflow/react@12.11` 的 React `MiniMapComponent` 把 `pannable = false, zoomable = false` 写成了**组件默认值**，再 `update()` 透传给内核；而内核 `XYMinimap.update()` 自己的默认值本来是 `true`。**组件默认值把内核默认值覆盖掉了** → 缩略图成为一个"死的缩略图"。
  - 另外读内核 `panHandler` 发现它只处理 `mousemove`/`touchmove`：**单击永远不会平移**，只有拖拽才会。
- 修复（`canvas/CreativeTree.tsx`）：
  1. `<MiniMap pannable zoomable />` —— 恢复拖拽平移 + 滚轮缩放；
  2. 补上**单击定位**：内核里缩略图 `<svg>` 的 `viewBox` 就是**流坐标**，`onClick` 也挂在 svg 上，于是按 `viewBox + getBoundingClientRect` 比例把点击位置换算成流坐标，`setCenter()` 跳过去（不依赖语义不明的库 `pointer()`）；
  3. ⚠️ 拖完松手浏览器还会补发一个 `click`，会额外跳一次 → 用画布容器的**捕获阶段 `mousedown`** 记录按点，位移 > 4px 判定为拖拽、忽略该 click。
- 顺手加固（同一区域观察到的竞态）：`fitView` 原本在节点数变化后 60ms 就调用，而 React Flow 用 `ResizeObserver` **异步**量尺寸 —— 实测偶发"尺寸没量到就 fitView"→ 视口停在 `matrix(1,0,0,1,0,0)`、缩略图空白。改为 **`useNodesInitialized()` 为真才 fitView**（未就绪时提前返回且不推进计数，就绪后会补上）。
- 验证：`probe-minimap.cjs` **10 断言**，全用真实鼠标事件，**连跑 3 轮 3/3 全绿**：
  尺寸/可见/未被遮挡 · 缩略图画出节点(4/4) · **拖拽 → 视口平移** · **拖拽结束无额外跳转（click 抑制生效）** · **单击定位方向正确** · **定位精度 1px**（落点 87,399 vs 目标 87,398）· **滚轮缩放**（scale 2.0000→1.2142）。

**D.6 画布外设深色主题（缩放控件 + 缩略图）**
- 现象（用户反馈）："放大缩小 fitView 锁定的图标看不清楚，图标和图标背景不明显"。
- 定位（先用计算样式量出数字，不靠肉眼猜）：`@xyflow/react` 的外设**默认是浅色主题**——
  - 控件按钮底色 `--xy-controls-button-background-color-default: #fefefe`（近白）；
  - 图标是 `fill: currentColor` + `color: inherit`，于是继承了 body 的浅色文字 `#e6edf3`。
  - **浅图标压近白底 ⇒ 实测对比度只有 1.06 ~ 1.17 : 1**（WCAG 非文本内容要求 ≥3:1），所以四个图标"糊成一片"。
  - 同源的还有缩略图：底色 `#fff` + 遮罩 `rgba(240,240,240,.6)`，压在我们 `#0d1117` 的画布上就是一块刺眼白板。
- 修复（`src/renderer/styles.css`，纯 CSS，零逻辑改动）：
  - 覆盖 xyflow 的**非 `-default` 变量名**（`--xy-controls-button-background-color` / `-color` / `-border-color` / `-box-shadow` 等）。其内部写法是 `var(该名, var(同名-default))`，所以填非 `-default` 名**必定生效且与 CSS 加载顺序无关**（`styles.css` 先于 App 引入的 xyflow `style.css`），也**不需要 `!important`**。
  - 尺寸是写死的（26px / 图标 12px），用更高特异性 `.react-flow .react-flow__controls-button`（0,2,0）盖过自带的（0,1,0）：按钮 28px、图标 15px；`:disabled` 的 `fill-opacity` 从 .4 抬到 .55。
  - 配色取项目既有令牌：面板 `#161b22` / 描边 `#30363d` / 图标 `#e6edf3` / 悬停选中色 `#1f6feb` + 白图标。

| 打包类（D.2） | 安装包安装后运行验证 |

## 5. 风险与回滚

- **依赖/原生模块问题**：已通过"零原生依赖"从根上规避（JSON 存储替代 better-sqlite3；纯 JS 栈无 `.node`）。若将来引入原生模块，需 `electron-rebuild` 对齐 Electron ABI。
- **网络（国内）**：`github.com` 常被挡（本机实测 502）。打包所需产物（Electron zip / winCodeSign / nsis）统一走 npmmirror，见 `scripts/dist.cjs`；已设同名环境变量时尊重用户设置。
- **Windows 符号链接特权**：`winCodeSign` 含 macOS 软链，解压需开发者模式或管理员，否则报 `客户端没有所需的特权`（只影响 exe 图标/版本信息）。详见 `electron-builder.yml` 顶部注释。
- **Shell 环境异常**：本机 WorkBuddy 的 bash shim 缺 `dirname`/`cd`/`cat`/`tail` 等基础命令，管道与文本汇总不可靠；git/文件操作统一用 Python（绝对路径）或 node 直接调用。
- **`node_modules/@types` 的隐式纳入陷阱**：TS 会**自动**把 `node_modules/@types/*` 全部当成全局类型库；本机 `node_modules` 是"不完整 npm 拷贝"混合体，若其中出现残缺 `@types`（如 `@types/glob` 缺 `index.d.ts`），会以 `TS2688` **打断整个类型检查**。对策：①三个 tsconfig 均显式 `"types": ["node"]`（不依赖隐式纳入）；②从 `.pnpm` 补包时**跳过 `@types/*`**。
- **每步可回退**：任一步失败立即停，汇报；必要时 `git revert <step-commit>` 回到上一步干净态。
- **密钥安全**：DeepSeek key 经 Electron `safeStorage` 加密后存 `<userData>/diverge/settings.json`，**绝不落明文、绝不进仓库**（系统无加密后端时才降级明文，且界面会明确警示）。`.gitignore` 已屏蔽 `.env` 等。
