# 发散创意画布桌面应用 · 开发计划（小步迭代版）

> 配套文档：`docs/发散创意画布桌面应用_方案.md`（纲领）、`docs/发散创意画布_实现计划_Phase0-1.md`（架构与代码骨架）
> 本文件是**执行层面的开发计划**，核心原则：**一个功能一步、做一步验证一步、每步本地提交、确认后再上传。**

---

## 0. 总原则与节奏

1. **极小步**：每个步骤只完成"一个可独立验证的功能点"，不贪大。
2. **先验证后继续**：每步做完，先按"验证方法"自测通过，再进入下一步。
3. **小步提交**：每步自测通过后，`git commit` 到本地 `main`（提交信息带步骤号，如 `step 3.2 deepseek adapter`）。
4. **确认后上传**：**不自动 push**。每完成一个阶段（或你口头确认"这步 OK"）后，才 `git push origin main`。
5. **可回退**：任一步验证失败，立即停下汇报，不强行往下做；必要时 `git revert` 该步提交回到干净状态。

---

## 1. 仓库与 Git 工作流

- **远程仓库**：`https://github.com/wmeng-dev/Canvas.git`（推断已存在，可能为空仓库；第 0 步核实）
- **本地仓库根**：`E:\Canvas`（即当前工作区，作为项目根）
- **默认分支**：`main`
- **目录约定**：
  - 应用代码在仓库根（`package.json`、`src/main`、`src/core`、`src/renderer` 等）
  - 文档归入 `docs/`（本文件及两份方案文档将移入 `docs/`）
- **`.gitignore`**（第 0 步创建，必须忽略）：
  ```
  node_modules/
  dist/
  dist-electron/
  .workbuddy/
  *.db
  *.db-wal
  *.db-shm
  userData/
  *.log
  .env
  ```
  > ⚠️ `.workbuddy/`、`.env`、`*.db`、`userData/` 含个人配置/密钥/本地数据，**严禁上传**。
- **提交粒度**：每步一提交；禁止把多步混在一个大提交里。
- **推送时机**：阶段 A/B/C/D 各自完成后（或你逐步确认后）`git push`；首次 `git push -u origin main`。
- **前置检查**：push 前确认本机已登录 GitHub（`gh auth status` 或 Git Credential Manager 已缓存令牌）。

## 3. 步骤清单（极细化）

> 每步格式：**目标 → 动作 → 验证 → 提交**

### 阶段 A · 工程地基

**A.0 仓库初始化**
- 目标：本地 `E:\Canvas` 成为 git 仓库并连上远程。
- 动作：
  1. `git init`（若未初始化）
  2. `git remote add origin https://github.com/wmeng-dev/Canvas.git`（已存在则 `git remote set-url`）
  3. 创建 `.gitignore`（见上）
  4. 将两个方案 md 移入 `docs/`
  5. 写 README.md（一行说明 + 仓库用途）
- 验证：`git remote -v` 显示 origin；`git status` 干净（忽略项不出现）。
- 提交：`step A.0 init repo & gitignore`

**A.1 package.json + tsconfig + 空目录骨架**
- 目标：工程元数据与 TypeScript 基线就位，目录占位。
- 动作：写 `package.json`（name/version/scripts 占位）、`tsconfig.json`、`tsconfig.node.json`；建 `src/main`、`src/core`、`src/renderer`、`src/shared` 空目录（各放 `.gitkeep`）。
- 验证：`cat package.json` 结构正确；`tsc --noEmit` 不报配置错误（空文件）。
- 提交：`step A.1 scaffold package/tsconfig/dirs`

**A.2 安装基础依赖**
- 目标：核心依赖装好且能解析。
- 动作：`pnpm add` electron react react-dom @xyflow/react zustand better-sqlite3 @modelcontextprotocol/sdk react-markdown；`pnpm add -D` vite @vitejs/plugin-react typescript @types/* electron-builder。
- 验证：`pnpm list` 能看到这些包；`node -e "require('electron')"` 不报缺失（或用 `pnpm why`）。
- 提交：`step A.2 install deps`

### 阶段 B · 核心能力（无界面也可验证）

**B.1 Electron 空壳能启动**
- 目标：运行后弹出窗口并显示一个占位页面。
- 动作：`src/main/main.ts` 创建 `BrowserWindow`；`src/renderer/index.html` + `main.tsx` 渲染 `<div>Diverge OK</div>`；`vite.config.ts` 配 renderer；`package.json` 加 `dev` 脚本（`electron .` + vite）。
- 验证：`pnpm dev` 打开窗口，显示 "Diverge OK"。
- 提交：`step B.1 electron shell boots`

**B.2 存储层：建库与建表**
- 目标：应用启动后生成 SQLite 文件并建好 5 张表。
- 动作：`src/core/storage/db.ts`（better-sqlite3，路径 `userData/diverge/diverge.db`）、`schema.sql`、建表。
- 验证：启动后 `diverge.db` 存在；用 `sqlite3` 或 `better-sqlite3` 脚本确认 5 张表存在。
- 提交：`step B.2 sqlite init + schema`

**B.3 存储层：基础 CRUD**
- 目标：能插入并读回 project / tree / node。
- 动作：`repositories.ts` 实现 project/tree/node 的 insert/select。
- 验证：写一段临时脚本调用 repositories，插入一条 project 并读回，打印成功。
- 提交：`step B.3 storage repositories crud`

**B.4 Generator 抽象层 types**
- 目标：定义统一接口，后续 adapter 都实现它。
- 动作：`src/core/generator/types.ts` 写 `ContentType / NodeSpec / NodeContent / Generator / GeneratorRegistry`。
- 验证：`tsc` 编译通过（纯类型，无运行逻辑）。
- 提交：`step B.4 generator types + registry`

**B.5 DeepSeek 直连 adapter**
- 目标：给定 prompt 能返回文本。
- 动作：`src/core/generator/direct/deepseek.ts` 实现 `DeepSeekGenerator.generate`（调用 `/v1/chat/completions`）。
- 验证：用临时脚本（或 later IPC）传入 prompt + 真实/测试 key，拿到返回文本并打印。
- 提交：`step B.5 deepseek direct adapter`

**B.6 示例 MCP Server**
- 目标：一个独立进程 MCP Server，暴露 `generate` tool。
- 动作：`src/core/mcp-server/workbuddy-mcp-server.ts`（用 SDK `Server` + `StdioServerTransport`，注册 `generate`）。
- 验证：`node` 启动该文件，用 MCP Inspector 或临时 client 连上，`listTools` 看到 `generate`。
- 提交：`step B.6 example workbuddy-mcp-server`

**B.7 MCP 接入：Manager + Adapter**
- 目标：主程序能拉起示例 Server 并成功调用其 `generate`。
- 动作：`McpClientManager.ts`（StdioClientTransport 拉起子进程）、`McpAdapter.ts`（tool → Generator）。
- 验证：主程序连上示例 Server，`callTool generate` 拿到返回文本。
- 提交：`step B.7 mcp client manager + adapter`

### 阶段 C · 界面与交互

**C.1 画布基础渲染**
- 目标：React Flow 显示几个固定节点。
- 动作：`src/renderer/canvas/CreativeTree.tsx` 用 `@xyflow/react` 渲染 2~3 个写死节点 + 连线。
- 验证：窗口画布显示节点与连线，可缩放/拖拽。
- 提交：`step C.1 react flow static canvas`

**C.2 节点点击 → 预览面板（文本版）**
- 目标：点节点弹出预览，先显示纯文本/占位。
- 动作：`PreviewPanel.tsx` 基础版（暂只渲染 text）；Zustand store 记录选中节点。
- 验证：点击节点出现预览面板，显示该节点文本。
- 提交：`step C.2 node click + preview panel (text)`

**C.3 生成对话框 + IPC 打通**
- 目标：选后端 + 提示词 → 经主进程生成 → 落库 → 节点显示。
- 动作：`panels/GenerateDialog.tsx`；`main/ipc/handlers.ts` 注册 `GENERATE_NODE` 调 `GeneratorRegistry`；preload 暴露；渲染进程调用。
- 验证：对话框输入 → 选 DeepSeek → 生成 → 新节点出现在画布且内容入库。
- 提交：`step C.3 generate dialog + ipc end-to-end`

**C.4 多类型预览**
- 目标：HTML / Markdown / SVG 各自正确渲染。
- 动作：`PreviewPanel` 分支：html→沙箱 iframe(srcDoc)；markdown→ReactMarkdown；svg→安全渲染。
- 验证：分别用三类样例内容验证渲染正确、脚本不越权。
- 提交：`step C.4 multi-type preview (html/md/svg)`

**C.5 发散/收敛交互**
- 目标：从节点继续发散生成子节点，旧版保留可翻案。
- 动作：节点右键"发散"→ 打开 GenerateDialog（默认父节点上下文）；生成 N 个子节点（限流并发）；保留历史版本。
- 验证：从节点 A 发散出子节点，树结构正确；旧节点仍在，可切回对比。
- 提交：`step C.5 diverge/converge interaction`

**C.6 AI 后端管理 UI**
- 目标：可视化配置 DeepSeek key、添加/启停 MCP server。
- 动作：`panels/AISourcePanel.tsx`；IPC `LIST_AI_SOURCES` / `ADD_MCP_SERVER`；配置持久化到 `ai_source` / `mcp_server` 表。
- 验证：填入 key 并保存后能用于生成；添加示例 MCP server 后出现在后端列表且可连。
- 提交：`step C.6 ai source management ui`

### 阶段 D · 收尾

**D.1 导出功能**
- 目标：最终方案导出 Markdown / 单文件 HTML。
- 动作：`panels/ExportPanel.tsx` + IPC `EXPORT`；Markdown 直接写；HTML 内联 CSS/JS 单文件。
- 验证：导出文件生成，双击/浏览器打开内容正确。
- 提交：`step D.1 export markdown + single-file html`

**D.2 Windows 打包**
- 目标：产出可安装的 exe/nsis。
- 动作：`electron-builder.yml`（appId/productName/win-nsis/icon）；`package.json` 加 `build` 脚本。
- 验证：本机 `pnpm build` 产出安装包；可安装并运行，功能与 dev 一致。
- 提交：`step D.2 windows packaging (nsis)`

### 阶段 E · 上传（按"确认后上传"）

- **E.1** 阶段 A 完成并你确认后：`git push -u origin main`
- **E.2** 阶段 B/C/D 各自完成并确认后：`git push origin main`

## 4. 验证方法汇总

| 类型 | 方法 |
|---|---|
| 启动类（B.1/C） | 运行 `pnpm dev`，肉眼确认窗口/画布现象 |
| 存储类（B.2/B.3） | 启动后检查 `diverge.db` 文件；临时脚本插入读回 |
| 纯类型（B.4） | `tsc --noEmit` 通过 |
| AI 类（B.5/B.6/B.7） | 临时脚本/Inspector 调 `generate`，打印返回文本 |
| 交互类（C.3/C.5） | 界面操作 → 观察节点/树/库变化 |
| 打包类（D.2） | 安装包安装后运行验证 |

## 5. 风险与回滚

- **依赖/原生模块问题**（better-sqlite3、MCP SDK 需 Electron ABI 重建）：遇 ABI 错误先 `electron-rebuild`，不绕过。
- **Shell 环境异常**：本机 Git Bash/PowerShell 输出捕获不稳定，执行 git 操作若异常，改用 WorkBuddy 内置 git 能力或让你在终端手动跑，我不瞎猜结果。
- **每步可回退**：任一步失败立即停，汇报；必要时 `git revert <step-commit>` 回到上一步干净态。
- **密钥安全**：DeepSeek key 只存本地 `userData`/数据库，绝不进 `.env` 或提交；`.gitignore` 已屏蔽。
